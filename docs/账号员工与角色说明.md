# 管理账号、员工与角色分配说明

版本：0.2.0；日期：2026-10-21。适用模型为“管理员专用权限平台、员工直接业务授权”。旧账号演示模式已迁移。

## 对象含义

| 对象 | 含义 | 是否具备平台密码 |
| --- | --- | --- |
| 员工 employee | 组织、岗位等资料及独立业务授权主体 | 无需具备 |
| 管理账号 account | 登录权限平台的凭据与会话主体 | 是，BCrypt 存储 |
| 管理角色 MANAGEMENT | 权限平台操作权限集合 | 不适用 |
| 业务角色 BUSINESS | 外部应用操作权限集合 | 不适用 |
| 应用接入方 integration_client | 可信业务后端及其可查询应用范围 | 使用独立应用密钥 |

“用户”是业务叙述中的泛称，当前数据库没有另外的 user 身份表。历史关系名 user_role 实际关联 account，不表示普通员工必须有账号。

## 两条授权链

管理账号 → user_role → 管理角色 → role_permission → 管理操作权限。登录本身需有效 platform:access，具体管理动作还需对应权限。默认管理员同样依靠显式角色授权，没有永久超级管理员绕过；不能通过普通管理接口停用或撤掉最后一个完整管理员。

员工 → employee_role → 业务角色 → role_permission → 业务权限。多个有效业务角色按并集合并；重复权限去重。员工、角色、权限及资源全部祖先均启用才有效。员工没有角色或权限时拒绝。普通员工无需登录权限平台，外部业务后端提交可信员工编号和固定动作权限进行鉴权。

账号可以不关联员工；关联时每个账号只关联一名员工、每名员工最多关联一个账号。关联用于资料对应，不自动复制账号角色，不影响员工独立业务授权。管理员即使关联员工，也不能凭管理 Cookie 在公文系统冒充该员工。

purpose 创建后固定，平台拒绝给员工分配管理角色、给管理账号分配业务角色，以及将管理权限与业务权限跨用途配置。原始 Excel 的组织、岗位、候选角色模板均不自动生成账号或真实授权。

## 本机验证对象

| 对象 | 使用方法 | 初始权限 |
| --- | --- | --- |
| project_admin | 8080 管理平台，测试密码 1234 | 完整管理权限，固定 30 分钟会话 |
| 公文编辑员工（合成） | 9090 选择 editor 身份，无员工密码 | office-editor：读取与修改 |
| 公文阅读员工（合成） | 9090 选择 reader 身份，无员工密码 | office-reader：只读 |

员工 ID 由各环境生成，以管理员页面或本机配置为准，不能将本机 ID 当作跨环境固定主键。现有开发库中两个公文样例编号为 10002、10003。旧 demo_user、flow_user 业务账号保留历史记录但停用，原会话回收；新环境只初始化首个管理账号。

## 管理操作

“员工角色分配”维护 employee_role；“管理账号角色”维护 user_role；“角色权限”维护 role_permission。授权更新携带独立版本，过期返回 409 并重新加载。事务提交后，随后开始的鉴权立即读取新权限；已经完成鉴权的请求可继续。公文身份选择是本机模拟，不是真实员工登录，下一阶段应对接业务身份源。
