# 新环境安装运行指南（Windows）

版本：2.0；更新日期：2026-10-22。适用对象：在独立 Windows 环境中安装、构建和验证本项目的开发或评审人员。

本指南适用于 0.2.0 员工直接业务授权版本。权限平台只供管理员使用，独立公文系统通过服务端接口鉴权。公文员工身份选择为本机合成验证，不代表真实员工认证。

## 1. 安装范围与前置条件

目标环境独立建立 MySQL 数据库及应用凭据，不依赖原开发设备。服务地址为目标设备自身的 `http://127.0.0.1:8080`，仅供本机访问。

准备具有安装权限的 Windows 账户、可用网络及本机 MySQL root 管理密码。终端使用 PowerShell。除明确切换目录的步骤外，所有命令均在项目根目录执行；根目录应包含 README.md、backend、frontend、document-system、database 和 scripts。

| 组件 | 版本要求或已验证基线 | 用途与检查命令 |
| --- | --- | --- |
| JDK | 21；开发基线 21.0.9 | 编译和运行 Spring 后端；`java -version`、`javac -version` |
| Node.js / npm | Node.js 24；开发基线 24.13.0 / npm 11.13.0 | 前端依赖与构建；`node -v`、`npm.cmd -v` |
| MySQL Server | 8.4；开发基线 8.4.8 | 本机 localhost:3306；`mysql --version` |
| Python | 3.12，包含 pip 与 tkinter | 本机初始化及辅助工具；`py -3.12 --version` |
| Git | 可用的 Git 客户端 | 克隆和版本更新；`git --version`；使用源码 ZIP 时可选 |

Navicat、Apifox及独立 Maven 安装均非启动前置条件。Maven Wrapper 固定下载 Maven 3.9.11；首次运行需访问 Maven、npm 与 Python 软件源。版本表表示本项目的运行基线，不代表已经测试全部其他版本组合。

安装组件后重新打开 PowerShell，确认检查命令均可执行。JDK 应同时提供 java 与 javac，JAVA_HOME 应指向 JDK 根目录；MySQL 的 bin 目录需要加入 PATH，或使用 MySQL 安装附带的命令行客户端。MySQL 服务名称可能因安装配置不同而变化。

## 2. 获取源码

项目仓库：[eason1125t/ooad-easontry](https://github.com/eason1125t/ooad-easontry)。私有仓库需要先获得访问授权并完成本机 GitHub 身份认证。

仓库所有者可在 Settings → Collaborators → Add people 添加协作者；受邀人员接受邀请后克隆。个人私有仓库的协作者具有读取和写入权限，授权范围参见 [GitHub 个人仓库权限说明](https://docs.github.com/en/repositories/managing-your-repositorys-settings-and-features/repository-access-and-collaboration/permission-levels-for-a-personal-account-repository)。仅分发特定版本用于评审时，可提供经过核验的源码 ZIP。

```powershell
git clone https://github.com/eason1125t/ooad-easontry.git
Set-Location ooad-easontry
```

预期结果：进入项目根目录。使用 GitHub Code → Download ZIP 或交付源码 ZIP 时，先解压，再进入包含 README.md 的目录。交付 ZIP 为生成时快照，版本可能落后于仓库。

出现 Repository not found 时，核对仓库地址、私有仓库授权和 Git 当前认证账户；未取得访问权时不能继续克隆。

## 3. 安装项目依赖

在项目根目录逐条执行：

```powershell
py -3.12 -m pip install --target .tools/setup-deps "PyMySQL[rsa]==1.1.2" "bcrypt==4.3.0" "openpyxl==3.1.5"
npm.cmd ci --prefix frontend
```

预期结果：Python 依赖安装到 `.tools/setup-deps`，前端依赖按 package-lock.json 安装到 frontend/node_modules。初始化工具自动加载上述 Python 目录；PyMySQL 的 rsa 扩展用于兼容 MySQL 密码认证。

每条命令成功退出后再继续。下载失败时处理网络或软件源问题，保留首个错误；不要在未安装依赖的状态下继续初始化或构建。

## 4. 创建独立开发空库

确认本机 MySQL 服务正在运行。以下名称必须可用于本项目：

| 对象 | 名称 |
| --- | --- |
| 开发数据库 | municipal_access_ooad_dev |
| 测试数据库 | municipal_access_ooad_test |
| 应用数据库用户 | municipal_ooad_app |
| 迁移数据库用户 | municipal_ooad_migrator |

若存在同名对象，先核实其用途和已有初始化状态；不得覆盖、清空或重复建立。开发库由本步骤创建，测试库及两名数据库用户由下一步骤创建。

在项目根目录打开 MySQL 客户端，密码在本机提示中输入：

```powershell
mysql -u root -p
```

在 `mysql>` 提示符中执行，不能直接在 PowerShell 中执行以下 SQL：

```sql
SOURCE database/environment/create-development-database.sql;
EXIT;
```

预期结果：创建 municipal_access_ooad_dev，查询结果显示 utf8mb4、utf8mb4_0900_ai_ci，table_count 为 0。SQL 不使用 IF NOT EXISTS；同名库已存在时应停止核实，不把已有数据库作为全新空库复用。

## 5. 初始化本机凭据

返回项目根目录的 PowerShell：

```powershell
py -3.12 scripts/setup_local.py
```

在“市政权限平台 · 本机初始化”窗口填写：

| 字段 | 填写要求 |
| --- | --- |
| MySQL root 密码 | 当前设备 MySQL 管理密码，仅用于创建项目限定的数据库用户和测试库 |
| 网页管理员用户名 | 建议保留 project_admin；3–64 位，以小写字母开头，其余为小写字母、数字、点、下划线或短横线 |
| 网页管理员密码 | 4–64 个字符，UTF-8 编码不超过 72 字节 |

仅用于本机合成数据验证时，可按项目测试约定将管理员网页密码设为 `1234`；此值不是内置默认密码，也不适用于正式部署。MySQL 管理密码、随机数据库用户密码与网页密码是不同凭据。

点击“配置本机环境”。预期提示“本机配置完成”，并生成：

- `.local/application-local.properties`：随机数据库凭据；应用用户仅有两个项目库的 DML 权限，迁移用户仅有两个项目库的结构与数据权限。
- `.local/bootstrap.json`：首次管理员用户名及其 BCrypt 密码哈希；不创建普通员工账号。
- `.local/setup-status.json`：初始化完成状态。

同时建立独立测试库。配置文件不纳入 Git，后端首次启动时才写入网页账号。初始化包含 MySQL 数据库与用户创建，部分失败时可能已有对象；应检查实际状态后处理，不反复执行或重置已有用户。仅出现“本机配置已存在”不代表服务可运行，仍需核实原配置完整性后再继续。

## 6. 首次构建与启动

从项目根目录逐条执行，每步成功后再执行下一步：

```powershell
npm.cmd run build --prefix frontend
Set-Location backend
.\mvnw.cmd -B -ntp -DskipTests package
java -jar target\access-platform-0.1.0.jar
```

预期结果：

1. 前端类型检查与 Vite 构建成功，生成 frontend/dist。
2. Maven 输出 BUILD SUCCESS，生成 backend/target/access-platform-0.1.0.jar，并包含前端产物。`-DskipTests` 表示本步骤仅构建，不代表集成测试已执行。
3. Spring 服务启动，Flyway 自动执行版本 1.1、2、3、4，建立表结构和合成种子，再根据本机配置初始化账号。
4. 终端保持运行，浏览器可访问 `http://127.0.0.1:8080`。

启动失败时先保留日志并定位首个异常，不继续使用来源不明的旧 JAR。8080 被占用时核实占用程序；不得直接结束未知进程。

## 7. 验证安装结果

另开 PowerShell 执行：

```powershell
Invoke-RestMethod -Uri http://127.0.0.1:8080/api/health
```

预期 `status` 为 UP。随后使用初始化时设置的密码登录：

| 入口 | 预期行为 |
| --- | --- |
| project_admin（或自定义管理员名） | 登录后直接进入管理工作台，无员工入口选择 |
| 公文 editor / reader | 完成下节配置后在 9090 选择合成身份；无权限平台账号密码 |

全新环境仅初始化一名管理员；V4 补充两个公文业务角色、两个合成员工、office 应用及读写权限，保留历史合成目录。17 张业务表另加 Flyway 历史表。当前开发库的完整来源导入数量不适用于新环境；员工 ID 由各环境分配，以页面实际值为准。

### 配置并启动公文系统

保持权限服务运行。另开终端回到项目根目录：

```powershell
py -3.12 scripts/configure_integration.py
.\scripts\Start-Documents.ps1
```

配置脚本使用已有项目应用账号，只在项目库建立限定 office 应用的接入方及密钥，写入被 Git 忽略的 .local/office-local.properties；不再要求 MySQL root。默认不覆盖已存在配置。启动脚本复用 backend/mvnw.cmd 构建 document-system，执行公文测试并监听 127.0.0.1:9090；H2 文件库在 .local/office-data 下独立保存公文。

预期 http://127.0.0.1:9090/office-api/health 返回 UP。访问 9090，选择编辑合成员工，读取两条公文并保存；阅读员工只可读。管理员在 8080 的“员工角色分配”中回收编辑员工的写权限后，原公文会话再次保存应返回 403 且不修改内容；恢复授权后可再次保存。

不使用 PowerShell 启动脚本时，可在 backend 目录执行 `.\mvnw.cmd -f ../document-system/pom.xml -B -ntp package`，成功后进入 document-system 目录执行 `java -jar target/document-system-0.1.0.jar`。该前台进程使用 Ctrl+C 停止。两个服务必须从各自目录启动，使相对本机配置导入正确。

三份原始 Excel 不在源码仓库，基本启动不需要这些文件。完整资料导入须另行取得授权文件并遵循首次初始化规则。完整数据库快照含员工资料、密码哈希和会话，不作为新环境默认种子。

## 8. 停止、重启与更新

前台运行时，在原启动终端按 Ctrl+C 停止；终端位于 backend 时执行 `Set-Location ..` 返回项目根目录。

后续可在项目根目录使用以下脚本管理后台进程：

```powershell
.\scripts\Start-Platform.ps1
.\scripts\Start-Documents.ps1
.\scripts\Stop-Documents.ps1
.\scripts\Stop-Platform.ps1
```

Start-Platform.ps1 默认重新构建；已有最新 JAR 时可添加 `-SkipBuild`。首次克隆没有 JAR，不应直接跳过构建。后台日志位于 `.local/backend.log` 和 `.local/backend-error.log`，停止脚本只处理其记录并核验属于本项目的进程。

Windows 锁定运行中的 JAR，重新构建前先停止对应进程。前台自行启动的进程应通过原终端停止，不能假定后台停止脚本已记录该进程。若 PowerShell 执行策略阻止脚本，可使用第 6 节的逐步构建启动命令，无需修改系统执行策略。

更新前先执行 `git status --short` 检查本地修改，保存变更后停止服务，再执行 `git pull --ff-only`、`npm.cmd ci --prefix frontend` 并重新构建。存在本地冲突或数据库兼容问题时停止并核实，不覆盖本机凭据或已应用迁移。

## 9. 可选开发工具

Apifox：创建独立模块并导入 `docs/api/openapi.json`，包含全部引用模型及鉴权组件；环境前置 URL 为 `http://localhost:8080`，路径已含 `/api`。先调用登录接口保存 Cookie，并从响应获取 csrfToken；写请求携带 X-CSRF-Token。浏览器 Cookie 不会自动共享给 Apifox，不沿用其他环境的会话。

公文契约另为 docs/api/documents.openapi.json，前置 URL 为 http://127.0.0.1:9090。RBAC 外部 POST /api/authorization/check 使用本机后端应用密钥，不使用管理员 Cookie；密钥不应保存到共享项目。

Navicat：使用目标设备 MySQL 连接进行检查即可。表结构由 Flyway 迁移，不需要重复执行整套建表脚本。数据库配置和接口工具项目均应在目标环境独立建立。

## 10. 常见故障与完成标准

| 现象 | 检查与处理 |
| --- | --- |
| java/javac 或 npm/mysql 命令不存在 | 检查安装与 PATH；重新打开终端；确认 JDK 而非仅安装运行时 |
| Python 缺少 tkinter 或依赖 | 使用包含 tkinter 的 Python 3.12，并完成第 3 节；不要启动多次初始化窗口 |
| 数据库或项目用户已存在 | 确认是否为既有项目环境；检查部分初始化状态，不删除或覆盖 |
| Maven 无法下载或无法构建 | 核对 JDK 21、网络和首个错误；Wrapper 不要求预装 Maven |
| JAR 无法替换或 8080 被占用 | 停止已确认属于本项目的进程，再重新构建；不结束未知程序 |
| 登录失败 | 使用本机初始化设置的账号密码；已有账号不会因修改 bootstrap 文件而重置 |
| 401 / 403 | 分别检查会话是否过期、是否缺少权限或 CSRF；不要仅修改页面路由绕过 |

安装完成标准：健康检查 UP、管理员可进入管理工作台、公文编辑员工可读写、同一业务会话撤权后拒绝且恢复后成功、退出后原会话失效。记录软件版本、源码提交号、执行步骤和结果；反馈错误时排除密码、Cookie、令牌及原始员工资料。

本指南已对照初始化源码、迁移种子、构建配置与锁文件核对，已在当前开发环境构建并完成双服务联调，尚未在独立全新 Windows 环境执行完整安装验收。后续应补充新环境实测证据；日常操作见[运行与使用](运行与使用.md)，当前演示见[首检演示脚本](首检演示脚本.md)。
