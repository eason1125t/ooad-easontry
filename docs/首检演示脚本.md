# 首检演示脚本

版本：2026-10-21；建议主线 8–10 分钟。对应当前本机 RBAC0，实际预演见[首检预演记录](首检预演记录.md)，成果导航见[首检交付目录](首检交付目录.md)。

## 演示前准备

打开 http://127.0.0.1:8080。若服务未启动，在项目根目录执行 `./scripts/Start-Platform.ps1 -SkipBuild`；需要重新打包时先按《运行与使用》停止本项目进程。健康检查为 `/api/health`。

管理员 project_admin、流程账号 flow_user，当前本机测试密码均为 1234。demo_user 用于独立展示已有员工关联，主线不调整它。MySQL 连接凭据不用于网页登录。

准备两个独立登录会话，推荐普通窗口加无痕窗口或两个浏览器配置。相同浏览器中，同一主机的两个普通标签页共享 Cookie，不能分别扮演管理员和员工。本机也已验证 localhost:8080 和 127.0.0.1:8080 分别登录可隔离会话；每个窗口内保持各自地址。

确认 flow_user 启用、未锁定、无员工关联；仅关联“流程演练阅读角色 A”。角色 A 仅有“查看演示文档 / demo.documents:read”，角色 B 无权限。主线只调整合成角色的文档权限，不调整平台管理角色、不绑定真实员工。如果前一次演练中断，先按文末恢复状态再开始。

## 讲解与操作

| 时间 | 操作 | 应出现的结果与讲解 |
| --- | --- | --- |
| 0:00–1:00 | 打开首页，展示登录窗口；project_admin 登录 | 可选择权限平台或员工入口。账号承载登录身份；员工资料可选，角色决定权限，三者职责不同 |
| 1:00–2:00 | 进入权限平台，展示工作台及账号管理 | 当前 3 账号、5 角色、504 资源节点、13 操作权限。来源资料与合成数据数量不同，不能把员工数当账号数或并发性能 |
| 2:00–3:00 | 打开“账号角色分配”，选择 flow_user，查看已选角色 | 仅选角色 A；无需更改和保存。账号—角色、角色—权限均为多对多，当前没有角色继承 |
| 3:00–4:00 | 在独立窗口以 flow_user 登录，点击“读取受保护文档” | 自动进入员工入口，无管理菜单。显示 1 项权限，读到 DOC-001、DOC-002 两条合成文档；无员工关联也能使用已授权功能 |
| 4:00–5:00 | 管理员打开“角色权限分配”，选择角色 A，搜索 demo.documents，取消勾选文档权限 | 保存前显示新增 0、回收 1；点击“保存授权配置”后出现已保存反馈。只取消勾选还没有提交 |
| 5:00–6:00 | 回到原 flow_user 窗口，再点击“读取受保护文档”，不退出或重登 | 显示“当前账号没有执行此操作的权限”。后端以新权限鉴权；无权属于 403，与会话失效 401 不同 |
| 6:00–7:00 | 管理员重新勾选并保存角色 A 的文档权限；员工再次读取 | 新增 1、回收 0；保存后员工原会话立即读取成功。页面显示的合成文档不代表已实现所有来源业务系统 |
| 7:00–8:00 | 指出会话倒计时；展示 ER 图和 OpenAPI / Apifox 资料 | 固定 30 分钟，从登录起计时，刷新、授权、切换入口不续期。精确到期边界由可控时钟集成测试验证，现场不必等 30 分钟 |
| 8:00–10:00 | 说明测试、范围和后续阶段，按需演示资源筛选/员工查找 | 当前为 RBAC0。本机完整接口复演通过 57 个请求；最新 15 项集成测试、4 项前端回归、18 项 HTTP 检查通过。角色继承、互斥、数据范围和性能目标留待后续 |

员工权限展示可能在刷新身份或读取操作后更新；验证即时生效应发起新的受保护请求，不能只看旧页面上的文档或权限文字。曾经读取的内容不是新的授权成功证据。

## 可选补充：两条授权路径

先为角色 B 也配置文档阅读权限，并给 flow_user 同时分配角色 A、B。回收 A 的文档权限后仍可读取，因为 B 的路径还在；再回收 B 的同一权限后才能拒绝。此补充只涉及合成文档，不给普通账号授予 platform:access。完整接口复演已覆盖该场景；现场时间不足可直接展示记录。

完成后必须恢复：flow_user 只选 A；A 只保留文档阅读权限；B 无权限。管理员、demo_user 的授权保持原配置。

## 出现意外时

- 401 或会话过期：在当前角色对应窗口重新登录，重新开始该段；不要把重新登录后的成功当作“同一会话即时生效”证据。
- 回收后仍成功：先确认已保存，再查看账号是否还有 B 等其他授权路径；从员工窗口再次点击读取。
- 409 配置冲突：重新加载配置，检查当前角色和已选项，再修改保存。
- 最后管理员保护：展示系统拒绝反馈即可，不为继续演示取消保护。
- 员工选择显示已占用：demo_user 已关联合成员工 #1；flow_user 保持无员工关联，不把来源员工绑定到共享演示账号。

最终退出演示窗口，检查角色 A/B 及 flow_user 恢复上述状态。若要用自动脚本准备和演练，`python scripts/run_walkthrough.py` 会调整固定合成对象，并重写 `完整操作流程结果.txt`；应先保存需要保留的人工补充记录。本轮复演采用单独报告保存，没有覆盖原 TXT。
