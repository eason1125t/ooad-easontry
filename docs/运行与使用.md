# 本机运行与使用

这是可运行的本机 RBAC0 初版，前端和 API 由同一个 Spring 服务提供。主地址为 `http://127.0.0.1:8080`；Apifox 使用 `http://localhost:8080`。只绑定回环地址，没有部署到公网。

## 账号

本机管理员为 `project_admin`，普通演示账号为 `demo_user`。用户本轮指定两者及测试账号使用 `1234`；完整说明在 `.local/测试账号.md`，不推送远程。程序没有内置这个默认密码，首次启动读取用户本机初始化产生的 BCrypt 哈希。需要对外部署时必须换成新的凭据，并审定 HTTPS、Cookie Secure、可信来源及运维边界。

## 启动、停止与构建

在项目根目录用 PowerShell：

```powershell
.\scripts\Start-Platform.ps1
```

该命令先构建前端，再用 Maven Wrapper 打包后端，后台启动并等待数据库健康检查。已经完成构建时可使用 `-SkipBuild`。如果 8080 已占用，它会停止继续启动，不关闭未知进程。

```powershell
.\scripts\Stop-Platform.ps1
```

停止脚本核验启动记录中的绝对 JAR 路径后，只关闭本项目记录的进程；不删除文件或数据库。Windows 会锁定运行中的 JAR，因此需要重新打包时先停止平台。本轮曾遇到 JAR 锁定导致 repackage 失败，关闭本项目旧进程后重新打包已成功。

也可分别执行：

```powershell
npm.cmd run build --prefix frontend
Set-Location backend
.\mvnw.cmd -B -ntp test
.\mvnw.cmd -B -ntp -DskipTests package
java -jar target\access-platform-0.1.0.jar
```

不要在 JAR 正运行时覆盖打包。前端开发模式使用 `npm.cmd run dev --prefix frontend`，地址为 5173，代理 `/api` 到 8080；正式本机演示优先用 8080，减少两个服务的依赖。

## 数据库与本机设置

- `.local/application-local.properties`：随机生成的应用及迁移账号密码，配置已被 .gitignore 排除。
- `.local/bootstrap.json`：首个管理员和演示账号的 BCrypt 哈希，账号表非空时不会再初始化或重置。
- `.local/server.json`：启动脚本记录的进程信息；日志位于 `.local/backend.log`、`.local/backend-error.log`。
- 开发库：municipal_access_ooad_dev；测试库：municipal_access_ooad_test。JUnit 动态配置强制使用测试库，测试合成记录保留在测试库便于检查，不清空数据库。

新电脑初始化时，先准备 MySQL 和独立开发空库，再在可用 Python 环境安装工具所需依赖，并运行 `scripts/setup_local.py` 的本机隐藏输入窗口。当前电脑已经完成，不要重复执行或覆盖已有数据库用户。

## 三份 Excel 首次初始化

当前已执行完整初始化，原件未改动。结果见 `docs/audit/import-result.json`。原始员工只导入资料，不自动建立可登录账号；候选角色模板全部 PENDING，不自动授予权限。合成演示与原始资料区分存储。

初始化工具默认只预检：

```powershell
python scripts/import_sources.py
```

只有在尚未导入的独立开发库中，明确追加 `--apply` 才会提交。已初始化时该命令拒绝重复执行，不覆盖或合并。当前桌面使用依赖加载器提供的 Python，工具依赖安装在 `.tools/setup-deps`；若系统 Python 不含审计所需 openpyxl，应使用配置完成的运行环境。

## 管理平台操作

1. 首页点击“账号密码登录”打开窗口。管理员登录后选择“权限管理平台”或“员工演示入口”；员工账号自动进入演示入口。管理、员工页面持续显示剩余时间；每个 API 由后端校验权限。
2. 账号管理中新建合成测试账号、设置显示名和密码；员工可不关联，也可点击“查找员工”，按编号、组织或合成姓名检索后选择。原始员工只显示编号，不按真实姓名/电话搜索；被其他账号关联的员工不可选。当前合成员工 #1 已被 demo_user 关联，新测试账号建议不关联员工。选择只更新表单，点击账号“保存”后才提交。
3. 建立角色，再到角色权限分配页为角色勾选明确操作权限。演示使用“查看演示文档”（demo.documents:read）。
4. 到“账号角色分配”页给账号选择角色并保存。账号支持搜索和翻页；授权项可按名称/编码查找，也可仅显示已选。筛选不会回收隐藏的已选项，保存前展示新增和回收清单，无修改时不提交。另一浏览器会话以测试账号登录，直接进入员工入口，读取受保护文档。
5. 回收授权后，在测试账号发起下一次文档请求；没有其他授权路径时返回 403。多个角色仍有该权限时继续成功，这是权限并集的预期行为。
6. 编辑账号、角色、目录或权限状态，使用页面返回的版本保存；409 表示配置已经变化，或操作违反最后管理员保护。重新加载后再决定，不直接覆盖。
7. 管理员可切换员工入口；普通账号没有管理平台入口，手动修改地址也不能获得管理 API 权限。账号无员工资料时显示空态。

固定会话在登录成功起 30 分钟到期，操作、刷新和切换入口都不延长。退出、账号锁定/停用或密码重置回收会话；单纯权限变更保留会话，但后续鉴权立即读取新权限。

本轮完整演练结果在 docs/完整操作流程结果.txt，可用账号 flow_user / 1234 复核员工入口。新建及重置网页密码当前允许 4–64 位，BCrypt 仍限制 UTF-8 最多 72 字节；部署时应重新审定密码策略。MySQL 管理、应用与迁移账号密码没有简化。

## Apifox 调试

只使用新项目 8950931、main、默认模块。OpenAPI 包含 `/api` 路径前缀，环境前置 URL 保持 localhost:8080，无需额外追加 `/api`。先发送登录请求，让 Apifox 保存 Cookie；从响应读取 csrfToken，写请求填入 X-CSRF-Token。Cookie 属于数据库会话，并不使用 JWT/Bearer Token。

接口设计、模型和鉴权组件已经导入；回读比较结果见测试记录。当前会话未提供 Apifox MCP 工具，实际通过桌面导入/回读，没有冒称 MCP 验证。Apifox 的“已发布”等默认状态不代表所有业务已验收。

## 当前限制

本轮为简单可运行初版。未实现数据范围、角色继承/互斥、临时账号生命周期、增量导入、通用导入页面、组织编辑/HR 自动同步，以及物理删除管理对象。原始角色模板歧义仍待审定；原始目录不会因导入自动出现 359 个业务页面。

万级并发与 30ms 尚未定义统计口径及压测环境，因此没有达标结论。正式首检前仍应根据教师要求复核文档、扩大异常场景，并进行一次人工完整演练。
