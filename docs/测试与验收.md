## 真实页面检查

使用本机 8080 的打包版本、浏览器窄屏视口实际操作：

1. 管理员登录后出现入口选择，进入管理工作台，显示真实配置计数。
2. 角色管理中新建 ui-review，编辑名称为“界面验收角色（已验证）”；两次保存均成功，稳定编码禁改，数据库保留该合成角色。它未分配给任何账号，也没有权限。
3. 管理员切换员工入口，显示未关联员工/组织的明确空态。
4. 界面退出后回到登录页；demo_user 登录直接进入员工入口，没有管理导航或切换入口。
5. 普通账号点击“读取受保护文档”，后端检查通过并显示两条合成文档。
6. 普通账号手动访问 /#/manage/roles，被导航回员工入口。服务端越权另由集成测试验证。
7. 先前实际会话到期后，页面要求重新登录；精确时刻以可控时钟测试为准。

## 来源与 Apifox 核对

实际导入 111 个来源组织、10,000 名来源员工、18 个应用、115 个模块组、359 个功能点和 1,795 个 PENDING 模板单元格。I340 真空白存 NULL；合并单元格按锚点解析。加上合成数据，开发库为 113 个组织、10,001 名员工、504 个资源节点；完整授权演练新增 flow_user 与两个演练角色后，网页账号为三个，角色为五个。

来源预检校验原件哈希、唯一来源用户名和全部组织路径。已验证首次导入与重复拒绝；没有人为注入中途数据库故障来实测导入事务回滚，该场景保留待扩展，不以代码中的 rollback 当成已执行证据。

Apifox 新项目 8950931、main、默认模块 8746079。通过桌面界面导入，再读取保存的 OpenAPI 导出文件进行比较，验证方式为桌面导入与文件比较，未使用 Apifox MCP。比较覆盖方法/路径、operationId、摘要描述、参数、请求响应、状态码、Cookie 鉴权、CSRF、需求编号、权限编号、实现状态及全部模型。忽略模块标题/版本、3.0 补丁版本、可选 false、空容器/说明/示例及无语义数组顺序；差异列表为空。没有在 Apifox 中逐条手工发送所有接口。

## 复现命令

以下要求本机初始化已完成、MySQL 可用。测试只使用独立测试库；不要执行 clean 或数据库清空。

```powershell
npm.cmd run build --prefix frontend
Push-Location backend
.\mvnw.cmd -B -ntp test
Pop-Location
python scripts/verify_apifox.py
python scripts/verify_platform.py
```

最后一项要求平台正在 8080 运行，并通过隐藏输入读取网页管理员密码；也可由测试进程的 PLATFORM_TEST_PASSWORD 环境变量提供。原开发环境的契约验证依赖位于 .tools/validation-deps；新环境需另行安装 jsonschema、openapi-spec-validator 及初始化工具依赖，并核实脚本依赖加载路径。账号说明见 .local/测试账号.md。

一次 Maven verify 在测试全部通过后因旧 Java 进程锁定 JAR 而打包失败；仅停止已确认属于本项目的旧进程后，重新 package 成功并启动。首次 V1 的 MySQL CHECK 兼容错误与迁移修复见《数据库设计》，上述失败与修复过程均保留记录。

## 剩余验收与建议

尚未压测万级并发或 30ms；这些指标需要先明确 QPS/并发含义、接口、P95/P99、硬件和网络范围。没有完整覆盖每种非法字段、全部 26 个接口的每个响应码或多标签竞争场景，也未完成生产安全加固。真实浏览器授权保存已在后续首检预演中补验，见文末记录。

建议首检前由使用者走一遍“新账号 → 角色 → 文档读取 → 回收后拒绝 → 多角色保留路径 → 普通账号无管理权限”的完整演示，并核对教师要求的文档模板。之后再按计划扩展 RBAC1/RBAC2；原始角色模板的歧义应先审定，不能为演示直接批量授权。
