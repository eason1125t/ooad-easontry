# 公文系统运行与联调指南

版本：0.2.0；适用于已完成本机初始化的 Windows 环境。首次安装见[新环境安装运行指南](新环境安装运行指南.md)。

## 启动与停止

在项目根目录执行。权限平台首次启动会应用 V4；成功后才创建公文接入凭据。

```powershell
.\scripts\Start-Platform.ps1
py -3.12 scripts/configure_integration.py
.\scripts\Start-Documents.ps1
```

已有最新 JAR 且源码未变化时可给两个 Start 脚本分别加 -SkipBuild；首次构建不能跳过。Start-Platform 构建不执行 MySQL 集成测试，Start-Documents 默认执行公文测试。Windows 会锁定运行中的 JAR，更新前依次运行 Stop-Documents.ps1、Stop-Platform.ps1，构建后重新启动。脚本仅停止已记录且路径核验匹配本项目的进程，端口被未知进程占用时会停止并提示。

```powershell
.\scripts\Stop-Documents.ps1
.\scripts\Stop-Platform.ps1
```

权限平台：<http://127.0.0.1:8080>；公文系统：<http://127.0.0.1:9090>。均只监听回环地址。本机管理员 project_admin，测试密码 1234；新环境以初始化值为准。旧 demo_user、flow_user 不再用于平台登录。公文系统无员工密码，选择“公文编辑员工（合成）”或“公文阅读员工（合成）”建立验证会话。

## 授权、回收与恢复演示

1. 在 8080 登录管理员，打开“员工角色分配”，点击“公文合成员工”查找两个合成对象；以实际列表 ID 为准。
2. 编辑员工分配 office-editor（读、写）；阅读员工分配 office-reader（只读）。在“角色权限”中可核对 office.documents:read / update。
3. 在 9090 选择编辑员工，读取公文、修改标题或正文并保存，预期成功且版本加一。
4. 保持该公文会话，在 8080 将编辑员工角色改为 office-reader 并保存；回到原页面再次保存，预期 403“权限不足”，公文及版本不变。前端按钮状态可能仍是上一次查询结果，后端每次保存都会重新检查。
5. 重新授予 office-editor 后，在原业务会话再次保存，预期成功。可点击重新读取刷新权限和公文；有未保存内容时先记录，避免重新读取丢失本地草稿。
6. 选择阅读员工，预期可读但不能保存。停用员工、角色、权限或上级资源同样使相应有效权限消失。

管理与业务使用不同 Cookie 名称。即使同一浏览器也不共享身份；8080 管理 Cookie 不能作为外部接口应用密钥。员工业务角色不接受浏览器自报。

## 自动联调与测试

启动两个服务后执行 `py -3.12 scripts/run_integration_walkthrough.py`。脚本仅修改固定合成员工授权与合成公文，完成后恢复原角色、标题和正文；成功保存会增加版本及业务审计，不伪造回滚历史。每次生成独立的 docs/audit/公文系统联调_时间.txt 与 .json。管理员测试密码可通过 PLATFORM_TEST_PASSWORD 环境变量覆盖，不在命令行传入。

后端测试（在 backend 目录执行）：

```powershell
.\mvnw.cmd -B -ntp test
.\mvnw.cmd -f ../document-system/pom.xml -B -ntp test
```

第一项使用独立 municipal_access_ooad_test MySQL 库；第二项使用内存 H2 与本机 HTTP 测试桩。现有资料库不作为测试库。真实网络联调、数据库集成测试与浏览器人工操作分别记录，不互相替代。

## 配置与故障定位

`.local/application-local.properties` 为权限库凭据；`.local/office-local.properties` 为应用密钥、两个合成员工编号及公文 H2 凭据。两者均不可上传。移动整个项目目录后，公文 H2 绝对路径需核对；不要误指向新的空文件而认为原数据丢失。

configure_integration.py 默认不覆盖既有配置；--rotate 创建新密钥并备份旧配置，旧密钥仍有效，待切换验证后用 --revoke 加明确公开凭据 ID 撤销。不要将密钥放入前端或共享 Apifox 环境。轮换后重启公文进程以加载配置。

日志在 .local/backend.log、backend-error.log、office.log、office-error.log。401 检查会话或应用凭据；403 检查权限、应用范围、CSRF 与 Origin；409 重新读取版本后处理冲突；503 检查权限服务、数据库及本机配置。公文服务无配置或两个员工编号无效时拒绝启动。权限服务不可用时不得使用旧结果放行。
